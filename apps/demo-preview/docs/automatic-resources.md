# Automatic work resource requirements

The work-selection step shows materials and machinery immediately. Quantities are calculated from `quantityPerUnit × exactQuantity`; the resource table basis has already been divided out during catalog extraction. Changing the work or quantity derives a fresh result without storing copied totals in React state.

`plannedResources` is shared by the display, material demand, machine demand, requisitions and assignment. Daily work splits retain total material demand. Equipment booking and actual execution use whole minutes, so each daily machine reservation rounds upward to the next minute; normative machine-hours remain visible separately. Material unit aliases include Cyrillic `д` as `dona`; mass and volume remain distinct stock records.

## Incomplete recipes

TIME entries without an audited counterpart still require a chief's technology-card resource calculation. An empty source list is labelled as unprovided separate consumption, never as proof that resources are unnecessary. Known labor-only asphalt rows 27-14-026 and 27-14-036 require material and machine clarification; 27-14-079 supplies machinery but requires a separate material calculation. Missing quantities are never generated by the AI module.

Manual calculations remain scaled from their entered work basis and are labelled as the chief's calculation. Combined IQN/manual plans carry both origins. A valid explicit NONE choice is displayed as the chief's decision. Existing labor, staffing, resource availability and chief dispatch checks remain in force.
